# Changelog

All notable changes to the Quasar AI delivery skills package are recorded here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
future package releases should use [Semantic Versioning](https://semver.org/).

This changelog begins with the current package baseline because no authoritative
earlier release history is available. Do not reconstruct older versions from file
timestamps; add a dated release only when the package version and release boundary
are deliberately established.

## [Unreleased]

### Added

- Added the public `q-tool-marp` shared tool for caller-owned Marp authoring, review, structural and security validation, capability probing, and local HTML, PDF, standard PPTX, title-image, or image-set rendering. It preserves editable Markdown, exact local theme CSS, local assets, render instructions, hashes, and runtime versions while keeping every render derived and non-authoritative; standard Marp PPTX is explicitly distinct from object-editable native PowerPoint. A pinned `@marp-team/marp-cli` 4.5.0 Node runtime refuses implicit installation, remote content, arbitrary config, source/output collisions, path or symlink escapes, and unauthorized overwrite or provenance-sidecar writes. Request/result schemas, valid and invalid fixtures, trigger cases, runtime tests, two original offline themes/templates, package checks, and contract markers cover direct use, delegated reporting, honest missing-runtime/browser fallbacks, and ownership preservation.
- Integrated the Marp channel into `q-report-deck` and `q-report-workflow`. Deck retains the report narrative, Quasar identity, slide plan, release, and artifact ownership while delegating only Marp mechanics; a released Marp bundle and its HTML, PDF, PPTX, or image derivatives remain tied to the exact baselined report source. The root `LICENSE` records the conceptual Softaworks reference, original theme/template status, Marp CLI license treatment, and a bounded exception for the audited `extract-zip` advisory in the unused browser-download dependency path.
- Activated the public `q-tool-pptx` shared tool for caller-owned PPTX inspection, extraction, slide selection, approved template fills, programmatic creation guidance, local rendering, contact sheets, and structural or visual validation. Its Python and Node backends are selected only after operation-specific capability checks, preserve sources through distinct outputs, bound untrusted ZIP/XML packages, reject macro-bearing or signed content, never follow external relationships or execute embedded content, and treat POTX/PPSX as read-only. Request/result schemas, valid and invalid fixtures, trigger cases, and cross-runtime smoke tests keep outputs derived with no semantic authority. `q-report-deck` may delegate PPTX mechanics while retaining plan, narrative, brand, release, and artifact ownership; `q-tool-pdf` remains optional validation support for an already exported PDF. Node creation is intentionally unavailable: PptxGenJS 4.0.1 pulled an `image-size` version affected by `GHSA-w3rx-r6r6-pgpr` and `GHSA-5p2g-fcmc-qvqq`, and no corrected `image-size` release was available; removing that unsafe creation dependency left the production Node tree at zero known vulnerabilities in the 2026-08-14 npm audit. The incoming implementation plan and preliminary Anthropic-derived bundle were reviewed only for functional boundaries; the root `LICENSE` records the provenance decision.
- Activated the public `q-tool-spreadsheet` shared tool for caller-owned XLSX inspection, extraction, bounded creation and editing, CSV/TSV conversion, recalculation, rendering, and structural or formula validation. Its original Quasar Python and Node backends select only capability-verified local routes, preserve sources through distinct atomic outputs, reject unsafe packages, never execute macros or external connections, compare exact formula-set hashes before committing recalculated candidates, and treat XLSM/XLTM/XLTX as read-only. Node requires ExcelJS 4.4.0 with an audited UUID 11.1.1 override instead of the vulnerable transitive range. Persisted outputs remain derived with no semantic authority; formulas, assumptions, figures, and business meaning stay with the caller. Market Analysis may use it only for a requested derived XLSX export while retaining calculation and published-result ownership. The incoming Anthropic-derived staging bundle and its restrictive license were reviewed only for functional boundaries and were not incorporated; the root `LICENSE` records the provenance decision.
- Activated the public `q-tool-document` shared tool for caller-owned DOCX/DOTX inspection, extraction, bounded creation, exact text replacement, comments, tracked replacements, accepted-change materialization, local DOC/ODT/RTF conversion, render-based QA, and structural validation. Independent standard-library Python 3.10+ and dependency-free Node 18+ backends share one dispatcher, refuse source replacement and pre-existing outputs without explicit `--overwrite`, reject unsafe or macro-bearing packages, and report honest gaps for cross-run edits, paragraph-mark/move acceptance, full XSD validation, LibreOffice conversion, and page rendering. Proposal Document and Report Document use it optionally while retaining meaning, branding, release, and artifact ownership; `q-tool-document` may use `q-tool-pdf` only for transient verification-PDF checks. The incoming Anthropic-derived staging bundle had restrictive terms that internal distribution could not cure, so no source prose, code, XML template, XSD, fixture, or guide was incorporated; the root `LICENSE` records the clean independent implementation and removed staging source.
- Activated the public `q-tool-pdf` shared tool for caller-owned PDF inspection, extraction, creation, transformation, forms, authorized security operations, OCR, rendering, and validation. It selects only between capability-verified local Python and Node backends, refuses source replacement and pre-existing outputs unless exact overwrite approval is passed as `--overwrite`, returns derived/no-authority outputs with provenance, and is an optional collaborator of Proposal Document, Report Document, and Report Deck without acquiring their meaning, release, or artifact-index ownership. The implementation is an independently authored Quasar design: the K-Dense/Anthropic PDF skill's public functional surface and restrictive source license were consulted at K-Dense commit `b2a92ba052dcae4ef48e850b9e31ebf75706be48` and Anthropic commit `f6656c1256d5a8adfa37db9110046ef20bac644c`, but no source prose, code, fixture, asset, guide, or license text was incorporated; the root `LICENSE` records the decision.
- Added a controlled Git side-effect vocabulary and executable policy cases for explicit approval, Prototype branch/worktree isolation, exact-path conflict staging, incompatible-conflict stops, unrelated-change preservation, planned-capability isolation, single-writer enforcement, root-only license ownership, TDD metadata, and link scope. The validator now reports 63 `contract_markers` separately from behavioral cases and ignores `tmp/` while retaining broken-link failures in distributable content.
- Added real Draft 2020-12 Proposal Document schema tests for `pattern`, `minLength`, `uniqueItems`, `$ref`, `$defs`, and `oneOf`, plus Markdown-frontmatter mapping tests and lazy dependency diagnostics.
- Added the public `q-review-evidence` read-only quality capability for bounded critique of supplied business, engineering, scientific, and clinical claims or evidence packages. It returns only a transient evidence-quality diagnostic; may read an explicitly authorized target URL but performs no open investigation or write; preserves caller ownership of confidence, synthesis, readiness, artifacts, and commitments; and conditionally loads confidence, bias, reasoning, quantitative, and scientific criteria instead of applying a clinical hierarchy universally. Scientific and clinical output is explicitly non-certifying. The skill adapts K-Dense Inc.'s MIT-licensed `scientific-critical-thinking` skill metadata version `1.2` at commit `13385c7c4db02fdcc84a020752c07cce91ef780e`, with complete license text and a file-level adaptation map in the root `LICENSE`.
- Added optional `q-review-evidence` collaboration to `q-research-investigate` for materially non-obvious finding confidence, `q-research-synthesize` for fragile material inferences, `q-code-research` for benchmark, vendor, compatibility, reproducibility, and ML/AI claims, and `q-proposal-discovery` as a bounded commitment-risk pilot. Every caller preserves its existing factors and names the expanded-review gap when the optional skill is absent; Discovery does not grade confirmed client statements, reuse Proposal Source `maturity`, or delegate readiness. `cited-findings.schema.yaml` remains unchanged pending a separate versioned decision supported by usage evidence.
- Added an opportunity-discovery route to the `q-ideation-session` product profile for improvement ideation over an existing product, service, or area. It runs as a `generate-options` sweep clustered by three declared effort and impact scales (`transformative`, `leverage`, `quick-win`), sweeps ten coverage categories as a divergence checklist, offers unsticking prompts, and adds three criteria to the product menu (`reach`, `frequency`, `defensibility-compounding`). Generated opportunities remain assumed hypotheses whose unknowns leave as routed evidence requests; existing intents, dispositions, gates, and baseline mechanics remain intact, and the route requires at least one traceable current-state input—either a versioned artifact or bounded transient orientation—without investigating anything itself. Optional-ideation triggers in `q-proposal-workflow` and `q-delivery-workflow` now name opportunity discovery. The route adapts Softaworks' MIT-licensed `game-changing-features` skill at commit `3027f20f3181758385a1bb8c022d4041dfb4de84`, dropping its emoji scoring, stack-rank-as-decision, in-session research, output location, and "10x" branding; attribution is centralized in the root `LICENSE`.
- Added the public `q-tool-humanizer` shared tool for English and Spanish prose with three bounded tasks: `detect` reports localized AI-writing indicators without an authorship verdict, `rewrite` removes clustered indicators, and `improve` applies a separate clarity-and-concision taxonomy to human or AI-assisted text. Four language-specific references keep pattern and clarity meanings separate, other languages return honest partial coverage, outputs remain transient unless a named file write is explicitly authorized, citations route to their evidence owner, and an immutable-content check prevents invented facts, lost qualifiers, or strengthened claims. The design adapts Softaworks' MIT-licensed `humanizer` and `writing-clearly-and-concisely` skills at commit `3027f20f3181758385a1bb8c022d4041dfb4de84`, Wikipedia contributors' CC BY-SA 4.0 field guide, and public-domain Strunk composition principles; file-level attribution and license scope are centralized in the root `LICENSE`.
- Added the public `q-tool-c4` capability for direct or delegated C4 modeling of systems, subsystems, containers, components, code areas, dynamic flows, deployments, and landscapes. It corrects the C4 taxonomy to four static zoom levels plus supporting views, preserves the caller as semantic owner, validates structured request/result contracts, detects local backends without installing anything, defaults to the verified Quasar Mermaid runtime when suitable, and conditionally supports Structurizr DSL for synchronized model/view work or C4-PlantUML for verified layout and styling controls. Source, optional Structurizr manual layout, and renders have separated authority and provenance; four runtime tests, request/result fixtures, semantic checks, and four contract markers cover abstraction, routing, reporting reuse, and honest capability gaps.
- Integrated C4 conditionally into `q-plan-architecture`, `q-plan-features`, and both report renderers. Architecture remains canonical in narrative and ADRs; feature modules map to C4 components only inside one confirmed container; report sources identify an exact approved C4 artifact version and view while document/deck skills retain channel layout and never reconstruct a model from a render. The cross-workflow contract, artifact outputs, catalog, derived interaction digest, and routing guide now preserve the same ownership split.
- The implementation is an original Quasar rewrite conceptually informed by Softaworks' MIT-licensed `c4-architecture` skill at commit `3027f20f3181758385a1bb8c022d4041dfb4de84` and verified against the official C4, Mermaid, Structurizr, and C4-PlantUML documentation. - Added the public `q-plan-design-system` conditional planning stage between feature decomposition and backlog planning, with `initial-definition`, `adopt-and-reconcile`, and `evolve-and-migrate` modes. It owns reusable design contracts — applicability, art direction and its authorized sources, design principles, token taxonomy, component and pattern inventory with stable IDs, states, accessibility contracts, responsive and localization rules, coverage, and governance — and authors two related `Working` artifacts with separated authority: `05b-design-system.md` for the contracts and `05b-design-tokens.json` for machine-readable token values, aliases, themes, and modes.
