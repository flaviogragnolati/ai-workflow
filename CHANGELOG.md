# Changelog

All notable changes to the Quasar AI delivery skills package are recorded here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and
future package releases should use [Semantic Versioning](https://semver.org/).

This changelog begins with the current package baseline because no authoritative
earlier release history is available. Do not reconstruct older versions from file
timestamps; add a dated release only when the package version and release boundary
are deliberately established.

## [Unreleased]

### Added

- Added the public `q-tool-c4` capability for direct or delegated C4 modeling of systems, subsystems, containers, components, code areas, dynamic flows, deployments, and landscapes. It corrects the C4 taxonomy to four static zoom levels plus supporting views, preserves the caller as semantic owner, validates structured request/result contracts, detects local backends without installing anything, defaults to the verified Quasar Mermaid runtime when suitable, and conditionally supports Structurizr DSL for synchronized model/view work or C4-PlantUML for verified layout and styling controls. Source, optional Structurizr manual layout, and renders have separated authority and provenance; four runtime tests, request/result fixtures, semantic checks, and four acceptance scenarios cover abstraction, routing, reporting reuse, and honest capability gaps.
- Integrated C4 conditionally into `q-plan-architecture`, `q-plan-features`, and both report renderers. Architecture remains canonical in narrative and ADRs; feature modules map to C4 components only inside one confirmed container; report sources identify an exact approved C4 artifact version and view while document/deck skills retain channel layout and never reconstruct a model from a render. The cross-workflow contract, artifact outputs, catalog, derived interaction digest, and routing guide now preserve the same ownership split.
- The implementation is an original Quasar rewrite conceptually informed by Softaworks' MIT-licensed `c4-architecture` skill at commit `3027f20f3181758385a1bb8c022d4041dfb4de84` and verified against the official C4, Mermaid, Structurizr, and C4-PlantUML documentation. No external text, template, or code was incorporated, so no third-party notice applies.
- Added the public `q-plan-design-system` conditional planning stage between feature decomposition and backlog planning, with `initial-definition`, `adopt-and-reconcile`, and `evolve-and-migrate` modes. It owns reusable design contracts — applicability, art direction and its authorized sources, design principles, token taxonomy, component and pattern inventory with stable IDs, states, accessibility contracts, responsive and localization rules, coverage, and governance — and authors two related `Working` artifacts with separated authority: `05b-design-system.md` for the contracts and `05b-design-tokens.json` for machine-readable token values, aliases, themes, and modes. It chooses no UI library, writes no component code, produces no wireframes or final art, publishes nothing externally, and assigns no priority.
- Added `design_system_ref` to the workflow-state schema as the single runtime reference: the specification version it names resolves the compatible token set, and no second global field is introduced. Package validation now keeps `not_applicable`, an accepted omission, and an executed run distinguishable, requires a reference for a completed stage, rejects one for a `not_applicable` stage, and requires a registered design token set to reference its specification in `source_refs`. Valid and invalid workflow-state and artifact-index fixtures cover each branch, and three acceptance scenarios cover conditional routing, the artifact-authority split, and honest validation limits.
- Added a `Design system reference` section to the cross-workflow contract, and conditional routing to `q-delivery-workflow`: one routing question after features, reconciliation of a completed run into `design_system_ref`, an accepted omission recorded as a decision and risk rather than as `not_applicable`, and design-system coverage inside integral QA.
- Added interface ownership upstream and design-system consumption downstream: `q-plan-tech-foundation` now records the visual platform, UI library, styling and documentation tooling, accessibility target, and token format and validator with exact versions; `q-plan-features` owns interface surfaces and states without choosing components; `q-plan-architecture` may reference the system from application standards without duplicating it; and `q-plan-backlog`, the three grills, `q-code-implementation-plan`, `q-code-tickets`, `q-code-implement`, `q-code-prototype`, `q-review-code`, and `q-review-codebase` load the exact referenced version. Design-system conformance is a criterion inside the standards axis of change review and codebase audit, never a third authority axis.
- Added honest validation limits to the design-system stage: a token set is emitted only from confirmed values, is checked directly on its persisted path with the project's own confirmed command, and is never produced by installing tooling silently. Missing confirmed values or an unresolved brand or accessibility decision block the stage; an unavailable validator instead returns `completed_with_warnings` with an explicit `token_validation: unverified` gap carried to implementation and QA, matching how the package already reports unverified stack and diagram coverage rather than issuing a false approval. Planning records the accessibility target and expected evidence and never claims conformance. The capability was motivated by an external MIT-licensed `design-system-starter` skill, but the implementation is an original Quasar rewrite against these contracts; no text, checklist, or template was incorporated, so no third-party notice applies.
- Added the public `q-research-market-analysis` conditional Research stage and the `market` research profile for evidence-linked measurement normalization, market sizing, TAM/SAM/SOM, top-down and bottom-up reconciliation, deterministic forecasts and sensitivity, unit checks, competitor matrices, market shares, CRn, HHI, demand segmentation, scenarios, and custom-method lineage. It owns one authored, `Working`, supporting `market-analysis.yaml`; JSON/CSV workspaces remain transient or explicitly registered derived exports with no semantic authority, and only promoted `published_results` may feed Synthesis or Reporting. The stage makes no network read and explicitly excludes participant contact, primary-fieldwork operations, PII/recording storage, and raw survey-response processing.
- Added standard-library, local-only market-analysis CLIs, valid and invalid fixtures, sixteen deterministic script tests, schema and semantic validation, conditional-routing acceptance scenarios, and a complete example artifact. The measurement-first sizing, reconciliation, forecast, sensitivity, unit-consistency, competitor-matrix, and ethics methods adapt K-Dense Inc.'s MIT-licensed `market-research-reports` skill at commit `13385c7c4db02fdcc84a020752c07cce91ef780e`; full attribution and the file-by-file adaptation map ship in `q-research-market-analysis/THIRD_PARTY_NOTICES.md`.
- Added the `market-research` Reporting content profile, independently of existing `report_type` values, with modular section guidance and typed finding, calculation, assumption, analysis-result, and scenario references that must resolve to exact source-snapshot versions. Reporting communicates promoted results and qualifiers without investigating or recalculating.
- Added the public `q-ideation-session` capability for structured, traceable ideation on one decision: `scientific`, `product`, `consulting`, and `general` profiles, four intents, four participation modes, independent generation with explicit provenance, predeclared weighted criteria, non-compensatory gates, adversarial review, routed evidence requests, and per-candidate dispositions. It ships an Ideation Register, an approved Ideation Baseline, an optional derived evaluation, and offline standard-library CLIs that scaffold, validate, score, and freeze the record without any network or model call. The method and the scaffold, validation, and matrix CLIs adapt K-Dense Inc.'s MIT-licensed `scientific-brainstorming` skill, generalized from scientific research to product and consulting work, with in-session literature search replaced by typed handoffs to the Quasar research, technical-research, and prototype owners; attribution ships in the skill's `THIRD_PARTY_NOTICES.md`.
- Added the `ideation` manifest group, the shared `ideation-baseline` schema in `q-core-contract`, its valid and invalid package fixtures, snapshot semantics in the package validator, and three acceptance scenarios covering ideation boundaries, adoption routing, and method discipline.
- Added a `Structured ideation` section to the cross-workflow contract: approved-snapshot authority, the `adopt-as-supporting-input`, `retain-as-independent`, `defer-decision`, and `reject` dispositions, version eligibility, and the rule that the adopting workflow — never the session — performs the lifecycle transition.
- Added optional ideation collaboration to `q-proposal-workflow` and `q-delivery-workflow`, and snapshot-adoption limits to `q-proposal-discovery`, `q-proposal-design`, `q-plan-product-core`, `q-research-scope`, and `q-report-source`, so a candidate cannot become a client fact, an authorized research question, a requirement, an ADR, scope, price, schedule, or a commitment.
- Added the public `q-tool-database-schema` capability for transient, profile-driven physical design, relational schema review, document-model review, migration design, and supplied-evidence performance analysis. It delegates no execution, preserves domain, stack, architecture, implementation, and review ownership, and ships verified PostgreSQL and MongoDB profiles.
- Added conditional database-schema collaboration to domain modeling, architecture, deep and feature refinement, implementation planning, debugging, change review, codebase review, and delivery routing, with explicit fallbacks when the optional tool is unavailable.
- Added the public, independently installable `q-tool-mermaid` capability for Mermaid creation, revision, validation, bounded repair, local SVG/PNG/PDF and optional ASCII/Unicode rendering, transactional Markdown compilation, structured requests/results, provenance, profiles, fixtures, and offline runtime checks.
- Added the `tool` manifest group and optional `uses` collaboration contract with schema, fixture, package-validation, trigger, fallback, distribution, self-use, and hard-dependency overlap checks.
- Integrated `q-plan-domain-model` and `q-plan-architecture` as hard Mermaid-tool consumers while preserving their semantic ownership, and added conditional collaboration to selected planning, code orientation, documentation review, proposal web, and report renderer skills.
- Added the public `q-review-skill` read-only diagnostic, the internal `q-maint-skill-quality` acceptance companion, and package regression scenarios for their core boundaries. The design adapts the useful context-value, progressive-disclosure, freedom-calibration, and usability ideas from Softaworks' MIT-licensed Skill Judge while replacing its fixed universal score with evidence, severity, target authority, and behavioral checks.

### Changed

- Advanced the manifest schema from `1.3` to `1.4` for additive workflow `profiles`, `content_profiles`, and resolvable `stage_conditions`. The existing general Research route and general report sources remain valid when the new optional fields are omitted; no migration is required for legacy artifacts.
- Extended the Research Brief, cited Findings Register, Research Synthesis, Research Baseline, and Report Source schemas additively for market measurement, quantitative context, analysis refs, optional baseline refs, content profiles, and typed evidence. Proposal keeps its existing explicit research-baseline adoption dispositions and gains no new stage or authority.
- Advanced the manifest schema from `1.2` to `1.3` for the additive `ideation` group. No existing entry changes, and consumers without `q-ideation-session` continue through the declared fallbacks of the two optional consumers.
- Removed `THIRD_PARTY_NOTICES.md` file-presence and content assertions from the package validator; provenance guidance remains unchanged.
- Advanced the manifest schema from `1.1` to `1.2` for the additive `tool` group and `uses` relationship. Existing `requires` semantics remain unchanged; optional consumers continue through their declared fallback when Mermaid is not installed.
